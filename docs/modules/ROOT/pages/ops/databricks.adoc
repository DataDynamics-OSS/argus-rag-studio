= Databricks 기반 환경 설정

설정 화면의 *기반 환경*(`platform.base`)을 `databricks` 로 바꾸면 임베딩·생성 LLM·벡터 스토어·오브젝트
스토리지가 Databricks 규약(Foundation Model API / Mosaic AI Vector Search / Unity Catalog Volumes)으로
전환됩니다. 인증은 *Databricks Host + PAT 토큰* 하나를 네 축이 공유합니다.

이 문서는 전환에 필요한 설정 정보를 정리한 것으로, 일부 값은 Databricks 워크스페이스 관리자(엔지니어)에게
직접 받아야 합니다. *"엔지니어에게 요청할 값"* 을 한눈에 보려면 <<request,요청 항목 체크리스트>>로 이동하세요.

== 전환 동작 요약

* *자동 적용* — 기반 환경을 `databricks` 로 바꾸는 순간, 임베딩 모델·차원·메트릭, 벡터 스토어,
  스토리지 백엔드가 Databricks 권장 기본값으로 채워집니다. Host/PAT 를 입력하면 임베딩/LLM 의
  서버 URL·API 키도 자동으로 채워집니다(서버 URL=`{host}/serving-endpoints`, API 키=PAT).
* *수동 입력 필요* — Databricks 워크스페이스에서만 알 수 있는 고유 이름(serving 엔드포인트명,
  Vector Search 엔드포인트명, Unity Catalog 카탈로그/스키마/볼륨 등)은 직접 입력해야 하며, 설정 화면에서
  *빨간색 `*`* 로 강조됩니다.
* *적용 범위* — 전환은 *신규 컬렉션의 기본값·검색 동작* 에만 적용됩니다. 기존 컬렉션은 생성 시점 임베딩
  모델이 고정되어 그대로 유지됩니다(재임베딩하려면 새 컬렉션 생성·재인제스천 필요).

[#prereq]
== 사전 준비(엔지니어가 프로비저닝)

설정값을 받기 전에, Databricks 워크스페이스에 다음 리소스가 *미리 생성* 되어 있어야 합니다.

. *Model Serving 엔드포인트 2개* — 임베딩용 1개, 생성 LLM용 1개
. *Mosaic AI Vector Search 엔드포인트 1개* — 인덱스를 담을 컴퓨트
. *Unity Catalog Volume 1개* — 원본 문서를 저장할 Volume
. *PAT 토큰 1개* — 위 리소스 전체에 대한 권한(serving 호출 / Vector Search 인덱스 생성·쿼리 /
  UC Volume 읽기·쓰기)

[#request]
== 요청 항목 체크리스트

엔지니어에게 받아야 할 값과, 설정 화면에서 입력하는 위치(`config` 키 포함)입니다.

=== 0. 인증 — 기반 환경 탭

[cols="1,1,2",options="header"]
|===
| 받을 값 | config 키 | 설명
| Workspace URL (Host) | `databricks.host` | `https://<workspace>.cloud.databricks.com` 형태. 전 축이 공유.
| PAT 토큰 | `databricks.token` | Personal Access Token(`dapi…`). 임베딩/LLM/벡터/스토리지가 모두 재사용. 환경변수 `ARGUS_DATABRICKS_TOKEN` 로도 설정 가능.
|===

=== 1. 임베딩 — 임베딩 탭

[cols="1,1,2",options="header"]
|===
| 받을 값 | config 키 | 설명
| 임베딩 serving 엔드포인트명 | `embedding.model` | Model Serving 에 배포된 임베딩 엔드포인트 이름.
| 출력 차원(dim) | `embedding.default_dim` | 모델의 벡터 차원(예: 1024). 컬렉션 차원과 반드시 일치.
| 쿼리 instruction 규약 | `embedding.query_instruction` | instruction-aware 모델(Qwen3-Embedding 등)이면 서빙이 쿼리에 붙이는 지시문을 *글자 단위로* 받아 입력(벡터 공간 일치). 없으면 비움.
| (서버 URL) | `embedding.server_url` | `{host}/serving-endpoints` 로 자동 — 요청 불필요.
| (API 키) | `embedding.api_key` | PAT 토큰 재사용 — 요청 불필요.
|===

=== 2. 생성 LLM — 생성 LLM 탭

[cols="1,1,2",options="header"]
|===
| 받을 값 | config 키 | 설명
| LLM serving 엔드포인트명 | `llm.model` | Model Serving 에 배포된 챗/생성 LLM 엔드포인트 이름.
| (서버 URL / API 키) | `llm.server_url` / `llm.api_key` | Host·PAT 로 자동 — 요청 불필요.
|===

=== 3. 벡터 DB(Mosaic AI Vector Search) — 벡터 DB 탭

[cols="1,1,2",options="header"]
|===
| 받을 값 | config 키 | 설명
| Vector Search 엔드포인트명 | `retrieval.vector_store_databricks_endpoint` | 콘솔에서 미리 생성된 Vector Search 엔드포인트(컴퓨트) 이름.
| Unity Catalog · Catalog | `retrieval.vector_store_databricks_catalog` | 인덱스를 만들 카탈로그(예: `main`).
| Unity Catalog · Schema | `retrieval.vector_store_databricks_schema` | 인덱스를 만들 스키마(예: `argus`).
|===

[NOTE]
====
Argus 가 임베딩을 직접 계산해 밀어넣는 *Direct Vector Access 인덱스* 를 사용합니다. 인덱스 전체 이름은
`{catalog}.{schema}.{접두사}_c{컬렉션ID}` 로 자동 생성되므로, 엔지니어는 해당 카탈로그/스키마에 대한
*인덱스 생성·쿼리 권한* 만 보장하면 됩니다.
====

=== 4. 오브젝트 스토리지(Unity Catalog Volumes) — 오브젝트 스토리지 탭

[cols="1,1,2",options="header"]
|===
| 받을 값 | config 키 | 설명
| UC · Catalog | `object_storage.databricks_catalog` | Volume 이 위치한 카탈로그.
| UC · Schema | `object_storage.databricks_schema` | Volume 이 위치한 스키마.
| UC · Volume | `object_storage.databricks_volume` | 문서 저장용 Volume 이름. 경로 `/Volumes/{catalog}/{schema}/{volume}`.
|===

[NOTE]
====
이미지 라벨링·이미지 추출/분류용 버킷은 현재 단계에서 스토리지 백엔드와 무관하게 *S3* 를 사용합니다.
이 두 버킷은 Databricks 전환과 별개로 S3 설정을 유지하세요.
====

== 요청이 불필요한 값(자동 처리)

* 임베딩/LLM *서버 URL* — Host 로 자동 유도(`{host}/serving-endpoints`).
* 임베딩/LLM *API 키* — PAT 토큰 재사용.
* 임베딩 *기본 모델·차원·메트릭*, *벡터 스토어*=`databricks`, *스토리지 백엔드*=`uc_volumes` — 전환 시 자동 설정.

[TIP]
====
백엔드는 serving 인증에 PAT 를 자동으로 끌어쓰지 않고 `embedding.api_key` / `llm.api_key` 를 그대로
`Authorization: Bearer <key>` 로 보냅니다. 설정 화면은 Host/PAT 입력 시 이 두 키를 PAT 로 자동 채우므로,
화면을 거치지 않고 `config.properties` 만 편집할 때는 두 키에 PAT 를 직접 넣어야 합니다.
====

== 주의사항

* *차원·모델 일치* — 임베딩 모델/차원이 기존과 다르면 벡터 공간이 달라집니다. 신규 컬렉션부터 적용되며
  기존 문서는 재인제스천이 필요합니다.
* *벡터 재색인* — 벡터 스토어를 외부(Databricks)로 바꾼 뒤 설정 화면의 *벡터 재색인* 을 1회 실행해야
  PostgreSQL 정본의 임베딩이 새 인덱스로 적재되어 기존 문서가 검색됩니다. 자세히는
  xref:../kb/reindex.adoc[설정 변경·재인덱싱] 참조.
* *스토리지 전환* — 백엔드를 바꿔도 기존 객체는 자동 이동하지 않습니다. 전환 후 문서를 다시 인제스천하세요.

== config.properties 예시

설정 화면 대신 파일로 구성할 때의 최소 예시입니다(값은 엔지니어에게 받은 것으로 치환).

[source,properties]
----
platform.base=databricks
databricks.host=https://<workspace>.cloud.databricks.com
databricks.token=dapi....

# 임베딩 (serving)
embedding.provider=openai_compatible
embedding.server_url=https://<workspace>.cloud.databricks.com/serving-endpoints
embedding.model=<임베딩 serving 엔드포인트명>
embedding.api_key=dapi....            # = databricks.token
embedding.default_dim=1024

# 생성 LLM (serving)
llm.provider=openai_compatible
llm.server_url=https://<workspace>.cloud.databricks.com/serving-endpoints
llm.model=<LLM serving 엔드포인트명>
llm.api_key=dapi....                  # = databricks.token

# 벡터 검색 (Mosaic AI Vector Search)
retrieval.vector_store=databricks
retrieval.vector_store_databricks_endpoint=<Vector Search 엔드포인트명>
retrieval.vector_store_databricks_catalog=main
retrieval.vector_store_databricks_schema=argus

# 스토리지 (Unity Catalog Volumes)
object_storage.backend=uc_volumes
object_storage.databricks_catalog=main
object_storage.databricks_schema=argus
object_storage.databricks_volume=documents
----

전체 키는 xref:install/config.adoc[설정 레퍼런스], 화면 설명은 xref:ops/settings.adoc[설정] 참조.
