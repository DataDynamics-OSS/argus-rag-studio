= 한글 HWP/HWPX 처리

한국에서 가장 널리 쓰이는 한글(HWP) 문서를 RAG 에 넣기 위한 처리 방법입니다. HWP 와
HWPX 는 포맷 구조가 완전히 달라 처리 경로도 다르며, Argus 는 본문 추출·미리보기·근거
페이지·이미지 색인까지 *기능별로 최적 엔진을 나눠* 사용합니다. 이 문서는 그 전체 지도를
설명합니다.

== 지원 포맷

[cols="1,3"]
|===
| 확장자 | 구조

| `.hwpx`
| 신형. OWPML(OOXML 류) — *ZIP 컨테이너 + XML*(`Contents/section*.xml`). 구조가 명시적이라
  추출 정확도가 높다.

| `.hwp`
| 구형 5.0. *OLE/CFB(복합 파일) + zlib 압축 + 바이너리 레코드*. 본문은 `BodyText/Section*`
  스트림에 레코드로 저장된다.
|===

== 처리 지도 — 어떤 기능이 어떤 엔진을 쓰나

HWP/HWPX 는 단일 엔진으로 모든 요구(텍스트 추출·원본 레이아웃 렌더·이미지 추출)를
충족할 수 없어, 기능별로 엔진이 다릅니다. 문제가 생겼을 때 이 표에서 담당 엔진부터
확인하세요.

[cols="2,2,3", options="header"]
|===
| 기능 | 엔진 | 비고

| 본문 추출(색인)
| 순수 Python(`text` 전략) 또는 rhwp(`rhwp` 전략)
| 컬렉션 파싱 전략으로 선택. 아래 <<extract,본문 추출>> 참조

| 문서 미리보기(브라우저)
| `@rhwp/core` *WASM — 클라이언트 렌더*
| 서버 변환 없음, 에어갭 동작. S3 브라우저·문서 화면의 HWP/HWPX 미리보기

| 검색 근거 페이지("원본 페이지 보기")
| *HWP 렌더 서비스*(`hwp_render`) — 헤드리스 브라우저 + `@rhwp/core`
| 별도 배포 서비스. 아래 <<render,HWP 렌더 서비스>> 참조

| 문서 속 이미지 색인(이미지 캡션)
| zip/OLE 직접 추출 + VLM
| HWPX 는 본문 위치 정밀 연결까지, HWP 바이너리는 문서 단위. 아래
  <<images,이미지 색인>> 참조

| 이미지 라벨링의 문서→이미지 변환
| `@rhwp/core` WASM(기본) / LibreOffice(옵션)
| `image_conversion.hwp_engine` 설정. LibreOffice 는 HWP 필터가 있는 환경에서만

| 구형 오피스(.doc/.ppt/.xls)
| LibreOffice → PDF 변환 후 파싱
| HWP 가 아닌 구형 *MS 오피스* 담당. 아래 <<libreoffice,LibreOffice>> 참조
|===

IMPORTANT: LibreOffice(soffice)는 일반적인 설치에서 HWP 5.0·HWPX 를 열지 못합니다
(`source file could not be loaded`). 그래서 HWP 계열의 렌더·미리보기는 모두
*rhwp 계열*(`@rhwp/core` WASM, `rhwp_py` 파서)이 담당합니다.

== 본문 추출 — 두 가지 경로

같은 HWP/HWPX 문서를 컬렉션의 xref:kb/ingestion.adoc#parse-strategy[파싱 전략]에 따라
다른 경로로 처리합니다.

[cols="1,2,2"]
|===
| | 순수 Python (`text` 전략, 기본) | rhwp (`rhwp` 전략, 선택)

| 구현
| `app/ingestion/loaders.py` — HWPX 는 stdlib(zipfile+XML), HWP 는 `olefile`(BSD)로 OLE/zlib
  해제 후 레코드 파싱
| `rhwp`(Rust, MIT) 파서의 PyO3 바인딩 `rhwp_py`

| 의존성
| HWPX: 없음 · HWP: `olefile`(기본 포함)
| `rhwp_py` *별도 빌드 필요*(Rust 툴체인)

| 표
| 추출됨. HWPX 는 구조 기반으로 정확, HWP 바이너리는 열 수 기준 행 묶음(*병합 셀 근사*)
| *셀 병합·복잡 레이아웃까지 정확*하게 Markdown 표로 보존

| 각주·미주
| `[각주]`/`[미주]` 라벨로 본문 말미에 분리 적재
| rhwp 모델 기반 추출

| 이미지 위치 앵커(HWPX)
| 그림 등장 위치에 마커 — 이미지 캡션 정밀 연결(커버리지 높음)
| Markdown 이미지 토큰 기반 — *토큰화되는 이미지에 한해* 정밀 연결(부분 커버)

| 장점
| 의존성 가볍고 즉시 동작(빌드 불필요)
| 표·레이아웃 정확도 최상

| 단점
| 복잡한 병합 표는 정렬이 어긋날 수 있음
| 최초 빌드에 Rust 컴파일(수 분), 수식 등 일부 객체는 텍스트로 안 나옴
|===

NOTE: `layout` 전략은 PDF 전용(pdfplumber)이라 HWP/HWPX 에서는 `text` 와 동일하게 순수 Python
경로로 동작합니다. HWP/HWPX 에서 의미 있는 선택지는 *`text`(Python) ↔ `rhwp`(Rust)* 입니다.

=== 처리 원리(요약)

*HWPX* — ZIP 을 열어 `Contents/section*.xml`(OWPML)을 파싱합니다. 문단(`<hp:p>`)의 텍스트
런(`<hp:t>`)을 모으고, 표(`<hp:tbl>` → `<hp:tr>` → `<hp:tc>`)는 Markdown 표로, 각주/미주
(`<hp:footNote>`/`<hp:endNote>`)는 라벨링해 분리합니다. 그림(`<hp:pic>`)은 등장 위치에
마커를 남겨 이미지 캡션 주입의 앵커로 씁니다.

*HWP 5.0* — `olefile` 로 OLE 컨테이너를 열고, `FileHeader` 플래그로 압축/암호화 여부를
확인합니다. `BodyText/Section*` 스트림을 `zlib`(raw deflate)로 해제한 뒤 레코드를 순회하며
문단 텍스트(`PARA_TEXT`)·컨트롤(`CTRL_HEADER` 의 `tbl`/`fn`/`en`)·표(`TABLE`)를 식별해
본문·표·각주/미주로 재구성합니다.

=== 선택 가이드

* *대부분의 문서·빠른 시작* → `text`(순수 Python). 빌드 없이 동작하고 일반 문서엔 충분하며,
  HWPX 이미지 캡션의 위치 연결 커버리지도 더 높습니다.
* *표·셀 병합·복잡 레이아웃이 핵심* → `rhwp`. 예산서·서식 등 격자 데이터가 많으면 권장.
* *품질 비교* → 같은 문서를 두 전략으로 각각 인덱싱해 검색 결과를 비교한 뒤 컬렉션 기본값을
  정합니다(xref:kb/reindex.adoc[재인덱싱] 참고).

=== rhwp 활성화(빌드)

`rhwp` 전략은 네이티브 확장 `rhwp_py` 가 설치돼 있어야 활성화됩니다. Rust(cargo/rustc) 설치 →
`maturin` 빌드 → wheel 설치 순서이며, 자세한 단계와 버전 정책(rhwp 코어는 릴리스 태그로
통일, 바인딩 버전은 RAG Studio 버전과 일치)은
link:https://github.com/DataDynamics-OSS/argus-rag-studio/blob/main/backend/native/rhwp_py/README.md[`backend/native/rhwp_py/README.md`]
를 참조하세요.

설치되면 `GET /api/v1/embedding/parse-strategies` 에서 `rhwp` 가 `available:true` 로 표시되고,
컬렉션 생성/재인덱싱 화면에서 선택할 수 있습니다. 미설치 시 `(미설치)` 로 표시되며 선택 시
명확한 오류를 던집니다.

[[libreoffice]]
== LibreOffice 의 역할

LibreOffice(soffice)는 *HWP 처리의 주 엔진이 아닙니다* — HWP/HWPX 를 열지 못하는 환경이
일반적입니다. Argus 에서 LibreOffice 가 담당하는 것은 다음입니다.

* *구형 MS 오피스 파싱* — `.doc`/`.ppt`/`.xls` 는 순수 Python 로더가 없어 LibreOffice 로
  PDF 변환 후 파싱합니다. 워커 호스트에 LibreOffice 가 없으면 해당 포맷 인제스천이 명확한
  오류로 거부됩니다.
* *오피스 고충실도 미리보기* — doc/docx/ppt/pptx/xls/xlsx 를 PDF 로 변환해 레이아웃·도형·
  표를 원본대로 보여줍니다(미설치 시 기존 네이티브 미리보기로 폴백).
* *이미지 색인의 구형 오피스 경유* — 구형 오피스 문서 속 이미지는 LibreOffice 변환을 거쳐
  추출합니다(미설치면 해당 포맷만 건너뜀 — best-effort).
* *(옵션) 이미지 라벨링의 HWP→이미지 변환 엔진* — `image_conversion.hwp_engine` 을
  `libreoffice` 로 바꾸면 soffice → PDF → 래스터화 경로를 씁니다. *HWP 필터가 설치된
  LibreOffice 에서만 동작* 하므로 기본값은 `rhwp`(클라이언트 WASM, 서버 의존 없음)입니다.

설치 확인: 워커/백엔드 호스트에서 `soffice --version`. 동시 변환 수·타임아웃은 설정
(`image_conversion.office_*`)으로 조정합니다.

[[render]]
== HWP 렌더 서비스(hwp_render) — 근거 페이지 보기

검색 결과에서 *"이 청크가 원본 몇 페이지에서 왔는지"를 이미지로 보여주는* 기능은 별도
배포 서비스가 담당합니다. LibreOffice 가 HWP 를 못 열기 때문에, 미리보기와 같은
`@rhwp/core`(WASM) 엔진을 *헤드리스 브라우저(chromium)* 위에서 서버사이드로 구동합니다
(`extensions/hwp_render_server`).

=== 무엇이 가능해지나

* 검색 결과 hit 의 *원본 페이지 보기* — 청크 텍스트를 페이지 텍스트와 매칭해 페이지를
  추정하고(`GET /api/v1/documents/by-chunk/{chunk_id}/evidence`), 해당 페이지를 PNG 로
  렌더합니다(`GET /api/v1/documents/{uuid}/page/{n}`).
* 서비스 미설정(빈 URL) 시 근거 페이지 기능만 조용히 비활성화되고, 나머지 HWP 처리에는
  영향이 없습니다.

=== 배포와 연결

* *배포*: 에이전트 화면 → 서비스 배포에서 kind=`hwp_render` 선택(3부
  xref:infra/service-deploy.adoc[서비스 배포]와 동일 절차). CPU 렌더 단일 이미지로 GPU 가
  필요 없으며, 컨테이너에 한국어 폰트(fonts-nanum·noto-cjk)가 포함됩니다.
* *연결*: 배포가 완료되면 서비스 URL 이 설정 `hwp_render.url` 에 자동 주입됩니다(수동
  지정은 env `ARGUS_HWP_RENDER_URL`).
* *서비스 엔드포인트*: `/health`(헬스체크) · `/stats`(요청/렌더 카운터) ·
  `/pages-text`(페이지 텍스트 — 매칭용) · `/render`(페이지 PNG).

NOTE: 헤드리스 chromium 특성상 메모리를 많이 쓰고 렌더 호출이 직렬화됩니다. 처리량이
필요하면 인스턴스를 늘려 로드밸런서 뒤에 두세요.

== 문서 미리보기(브라우저)

S3 브라우저·문서 화면의 HWP/HWPX 미리보기는 *클라이언트 WASM 렌더링*(`@rhwp/core`)입니다.
서버 변환이 전혀 없어 에어갭 환경에서도 동작하며, 원본 레이아웃(글꼴·표·도형)을 충실히
보여줍니다. 색인용 본문 추출(위 `text`/`rhwp` 전략)과는 독립적인 경로입니다.

[[images]]
== 이미지 색인(이미지 캡션) 커버리지

문서 속 이미지(차트·표 캡처 등)를 VLM 으로 인식해 검색 가능하게 만드는
xref:kb/ingestion-pipeline.adoc[인제스천 보강 파이프라인]의 HWP 계열 커버리지입니다.
HWP 공공문서는 표·차트를 이미지로 붙이는 관행이 있어 효과가 큽니다.

[cols="1,2,2", options="header"]
|===
| 포맷 | 이미지 추출·VLM 분류 | 본문 위치 정밀 연결(캡션 주입 위치)

| `.hwpx`
| 지원 — ZIP 미디어에서 추출
| 지원 — `text` 전략은 그림 등장 위치 앵커(커버리지 높음), `rhwp` 전략은 Markdown 토큰
  기반(토큰화되는 이미지에 한해 — 수식/개체 내부 그림은 문서 말미 부록으로 폴백)

| `.hwp` (바이너리)
| 지원 — OLE `BinData` 에서 추출(검색 배지·문서 이미지 섹션·부록 주입)
| 미지원 — 본문 내 정확한 위치 연결은 보류(캡션은 문서 말미 부록으로 주입)
|===

== 한계

* *암호화·DRM* HWP(배포용 문서 포함)는 비밀번호 없이 추출할 수 없습니다.
* *구형 HWP 3.0*(별도 바이너리 포맷)은 미지원입니다 — HWP 5.0/HWPX 만 처리합니다.
* *수식·그림 등 객체* — 순수 Python·rhwp 모두 텍스트 본문 위주로 추출하며, 수식은 텍스트로
  복원되지 않을 수 있습니다(수식·개체 속 그림은 이미지 캡션의 부록 폴백으로 보완).
* *병합 셀* — 순수 Python(HWP 바이너리) 경로는 열 수 기준 근사라 병합이 많은 표는 정렬이
  어긋날 수 있습니다. 정확도가 중요하면 `rhwp` 를 사용하세요.
* *LibreOffice 로 HWP 열기* — 일반 설치에서는 실패합니다. HWP 계열 렌더·미리보기는 rhwp
  계열 경로를 쓰세요.

TIP: 스캔본(이미지) HWP 처럼 텍스트 레이어가 없는 경우는 어느 추출 경로도 텍스트를 얻지
못합니다 — 이때는 페이지를 이미지로 렌더링해
xref:kb/ingestion.adoc#parse-strategy[`vlm`] 전략으로 처리하는 방향을 고려하세요.
