= 임베딩·청킹·거리 메트릭

== 임베딩

임베딩은 문장을 의미를 담은 벡터(예: 1024차원)로 바꿉니다. 의미가 비슷하면 벡터도 가까워져,
단어가 달라도("환불"↔"반품") 검색이 됩니다. 프로바이더는 셋 중 하나입니다.

[cols="1,3"]
|===
| `OpenAI 호환` | 외부 임베딩 서버(`/v1/embeddings`) 호출. 대규모·GPU 활용에 적합. 서버 URL·모델 필요.
| `로컬` | FastEmbed(ONNX) 모델을 백엔드 프로세스에 직접 로딩(서버 불필요, 최초 1회 다운로드). 소규모·서버 없는 환경.
| `hash` | 의미 없는 더미 벡터. 동작 테스트 전용(실제 검색 품질 없음).
|===

CAUTION: RAG 벡터 컬럼은 `vector(1024)` 고정입니다. 1024차원 모델을 사용하세요(예: bge-m3,
multilingual-e5-large, mxbai-embed-large). 로컬은 1024차원 모델만 목록에 노출됩니다.

== 청킹

긴 문서를 검색 단위(청크)로 나눕니다.

[cols="1,3"]
|===
| `auto` (기본 권장) | 파싱 결과 내용으로 자동 선택 — 표·헤딩 있으면 markdown, 아니면 recursive. `parse_strategy=auto` 와 짝.
| `recursive` | 문단→문장 구분자 우선순위로 자르는 범용 기본값.
| `sentence` | 문장을 끊지 않고 묶음. FAQ·QA 류에 적합. *한국어 인식*(kss 있으면 kss, 없으면
  약어·소수점 보호 규칙 폴백)으로 "Dr. Kim"·"3.14"·종결어미를 정확히 분리.
| `paragraph` | 빈 줄(문단 경계)을 끊지 않고 `chunk_size` 이내로 묶음. 문단이 의미 단위인 산문·보고서에 적합
  (한 문단이 한도를 넘으면 recursive 로 폴백).
| `section` | *섹션 헤더* (마크다운 헤딩·setext·번호 `1.2`·`제N장`·`Chapter`)를 경계로 자르고 각 청크에
  상위 섹션 경로(breadcrumb)를 `section_path` 로 단다. markdown 보다 넓게 일반 텍스트 헤더까지 인식.
| `fixed` | 구조 무시, 고정 길이 윈도우로 하드 컷(`token` 단위와 함께 쓰면 *Fixed Token Chunking*).
| `markdown` | *구조 인식* — 표·코드블록을 원자 단위로 보존(중간에서 안 자름), 헤딩을 경계로 쓰고
  각 청크에 상위 헤딩 경로(breadcrumb)를 덧붙인다. `layout`/`docai`/`vlm` 파서(표를 Markdown 으로)와 짝.
  헤딩 컨텍스트로 연속성을 확보하므로 문자 오버랩은 적용하지 않는다. 마크다운 구조가 없으면 recursive 와 동일.
| `semantic` | *의미 경계 분할* — 문장을 임베딩해 인접 유사도가 급락하는 지점(주제 전환)에서 자른다.
  가장 정교하나 인제스천 시 *문장마다 임베딩*이 필요해 비용·시간이 더 든다. chunk_size 를 상한으로 지킨다.
|===

* *단위(chunk_unit)* — `char`(문자, 기본) 또는 `token`(tiktoken). `token` 은 임베딩 모델의
  토큰 윈도우(보통 512)에 맞춰 잘라 한도 초과·낭비를 막는다. 한국어·코드는 문자당 토큰 수가 달라
  `char` 로는 한도를 넘기기 쉬우므로, 정확성이 필요하면 `token`(예: 크기 512, 오버랩 64)을 권장.
  tiktoken 미설치 시 `char` 로 폴백.
* *청크 크기* — 단위에 따라 글자/토큰. char 는 800~1200, token 은 256~512가 무난.
* *오버랩* — 경계 문맥 끊김 완화. 보통 크기의 10~15%. 크기보다 작아야 함. 꼬리 시작을 문장/단어
  경계로 *스마트 스냅* 해 부분 단어 조각을 피한다(`markdown` 은 헤딩 컨텍스트로 대체하므로 미적용).
  오버랩은 `chunk_size` 안에 포함된다(예산 캡) — 즉 `chunk_size` 가 진짜 상한이다.
* *품질 가드* — `chunk_size` 의 10% 미만 짧은 청크는 노이즈 방지를 위해 이웃에 병합한다(한도 내).

각 전략·단위의 동작과 *예제*, 오버랩 스마트 절단·품질 가드·청크 위치 메타데이터·전략 선택 가이드는
xref:kb/chunking.adoc[청킹 처리 가이드] 에서 자세히 다룹니다.

TIP: 표가 많고 토큰 한도가 빡빡한 문서는 `parse_strategy=layout/docai/vlm` +
`chunk_strategy=markdown` + `chunk_unit=token` 조합이 권장 기본값입니다 — 파싱으로 살린
구조(표·헤딩)를 청킹·임베딩까지 그대로 전달합니다.

== 거리 메트릭

검색 시 질문과 문서의 유사도를 재는 방법으로, 컬렉션의 `distance_metric` 에 따라 pgvector 연산자가 분기됩니다.

[cols="1,1,3"]
|===
| 메트릭 | 연산자 | 설명
| `cosine` | `<=>` | 방향(각도) 기반 유사도. 정규화 임베딩의 표준(대부분 정답).
| `l2` | `<->` | 유클리드(직선) 거리.
| `inner_product` | `<#>` | 내적. 정규화 벡터에서는 cosine 과 같은 순위.
|===

거리 메트릭은 검색 화면·Chat·운영 트레이스·평가 Run 에 함께 표시됩니다.
