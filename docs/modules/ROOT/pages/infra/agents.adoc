= 에이전트·서버 관리

[NOTE]
====
*구조 초안* — 목차와 각 절에 담을 내용의 방향만 잡아둔 문서입니다. 실제 화면 기준
설명과 스크린샷으로 채워 완성합니다.
====

추론 서비스(임베딩·리랭커·VLM 등)를 올릴 *서버를 RAG Studio 의 관리 대상으로 등록* 하는
단계입니다. 에이전트가 설치된 서버만 원격 배포·모니터링·재시작이 가능하므로, 모델·서비스
준비(3부)의 첫 순서입니다. 화면: *관리 > 에이전트* 의 서버 관리/서비스 관리 탭.

== 에이전트란

다룰 내용:

* 에이전트의 역할 — 원격 서버에서 컨테이너/systemd 서비스를 대신 조작하는 상주 프로세스.
* 에이전트 없이 되는 것/안 되는 것(외부(수동) 서비스는 관측만 되고 제어 불가).
* 지원 런타임(docker / systemd)과 아키텍처(x86_64 / arm64) 주의점.

== 에이전트 설치·등록

다룰 내용:

* 에이전트 패키지 설치 절차(tar/rpm)와 기동 확인.
* 서버 관리 탭에서 등록(REGISTERED) 흐름 — 하트비트로 상태(연결됨/끊김)가 갱신되는 구조.
* 등록 해제·재등록 시 주의(배포된 서비스는 남는다).

== 서버 관리 탭 읽는 법

다룰 내용:

* 서버 목록의 상태 배지(초록/호박/빨강)·리소스(CPU/MEM/GPU) 의미.
* 하트비트 끊김 시 점검 순서(네트워크 → 에이전트 프로세스 → 서버).

== 서비스 관리 탭 읽는 법

다룰 내용:

* 전체 서비스 집계 화면 — 어떤 서비스가 어디에 떠 있고 상태가 어떤지 한눈에.
* 관리형 서비스와 "외부(수동)" 행의 차이.
* 서비스 재시작·중지·로그 확인 방법(파이프라인 코드 변경 후 워커 재시작이 필요한 경우 포함).
