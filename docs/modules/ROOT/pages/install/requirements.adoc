= 시스템 요구사항

[cols="1,3"]
|===
| Backend | Python 3.11, FastAPI(async), SQLAlchemy 2.0 + asyncpg
| Database | PostgreSQL 16 + *pgvector* 확장 (`vector(1024)` 컬럼, tsvector FTS)
| Object Storage | MinIO 또는 S3 호환(원본 문서)
| Frontend | Node.js + pnpm (Next.js 16 / React 19)
| 추론(선택) | 임베딩 서버 :8080, 리랭커 서버 :8081 — FastEmbed(ONNX). GPU 없이 CPU 동작 가능
| 생성 LLM | OpenAI 호환 서버 또는 Claude(anthropic SDK)
| 비전 LLM(선택) | `vlm` 파싱 전략에만 필요 — 비전 가능한 OpenAI 호환 엔드포인트(BYO, *GPU*). 생성 LLM 설정 재사용
|===

파싱 전략 중 `text`/`layout`/`docai` 는 백엔드 인프로세스(CPU)로 추가 서버가 필요 없습니다.
`vlm` 만 외부 비전 LLM 엔드포인트가 필요하며, 이는 운영자가 제공합니다(생성 LLM 과 동일).
선택적 vLLM 비전 서버 예시는 `deploy/docker-compose.infra.yml --profile vision` 참조 —
xref:../kb/ingestion.adoc[파싱 전략].

== 차원 제약

벡터 컬럼이 `vector(1024)` 로 고정이므로 임베딩 모델은 *1024차원* 이어야 합니다
(bge-m3, multilingual-e5-large, mxbai-embed-large 등). 다른 차원을 쓰려면 DDL 변경이 필요합니다.

== 오프라인/에어갭

임베딩 `로컬`(FastEmbed) + 리랭커 `local` 로 외부 서버 없이 의미 검색·재정렬이 가능합니다.
동작 검증만 필요하면 임베딩 `hash` 로 모델 다운로드도 생략할 수 있습니다(검색 품질 없음).
