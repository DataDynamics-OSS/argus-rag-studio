= 라우팅 개요

[NOTE]
====
*구조 초안* — 목차와 각 절에 담을 내용의 방향만 잡아둔 문서입니다.
====

문서가 여러 출처에서 계속 들어오는 환경에서 *"이 문서를 어느 지식베이스에 넣을지"를
규칙으로 자동화* 하는 기능군입니다. 5부의 문서들은 이 순서로 읽습니다: 소스 등록 → 정책
구성 → 인테이크 → 자동화(소스 워치) → 검토·개선. 화면: *RAG 문서 라우팅*.

== 왜 라우팅인가

다룰 내용:

* 수동 업로드의 한계(담당자가 컬렉션을 골라야 함)와 자동 배분의 효과.
* 분류(doc_type — 문서가 무엇인가)와 라우팅(어디로 보낼가)의 구분.
* 언제 도입할지 — 지식베이스가 2개 이상이고 유입 문서가 꾸준할 때.

== 동작 원리 (개념)

다룰 내용:

* 정책 = 라우터 단계 목록 + 폴백 + 검토 임계라는 구조.
* 비용 사다리 개념 — 무비용 규칙(경로/파일명/확장자/메타데이터)을 위에, 비용이 드는
  판단(내용 임베딩·LLM)을 아래에 두는 이유.
* 결정 로그와 검토 대기(저신뢰/폴백) — "자동화하되 사람이 감독"하는 운영 모델.
