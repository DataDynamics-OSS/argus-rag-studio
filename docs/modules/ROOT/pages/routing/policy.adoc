= 라우팅 정책 구성

[NOTE]
====
*구조 초안* — 목차와 각 절에 담을 내용의 방향만 잡아둔 문서입니다.
====

문서를 어느 지식베이스로 보낼지 정하는 *정책(라우터 단계 조합)을 만들고 검증* 합니다.
정책은 버전 관리되는 자산이라 언제든 이전 버전으로 롤백할 수 있습니다. 화면: 라우팅 >
*라우팅 정책* / *라우팅 테스트* / *내용 라우팅 기준* 탭.

== 라우터 종류

다룰 내용(종류별로: 언제 쓰는가 → 설정 방법 → 예시 규칙 → 비용):

* *경로 규칙(path_rule)* — 소스 내 경로 프리픽스/글롭. 드롭존 규약이 있으면 가장 정확.
* *파일명 규칙(filename_rule)* — 파일명 키워드·정규식.
* *확장자 규칙(extension_rule)* — hwp/hwpx → HWP 문서고 같은 포맷 기반 배분.
* *메타데이터 매칭(metadata_match)* — 자동분류 doc_type 등 메타데이터 값 비교.
* *내용 임베딩(content_embedding)* — 문서 선두 텍스트와 컬렉션 기준 벡터의 유사도.
  사전에 "내용 라우팅 기준" 탭에서 디스크립터 계산이 필요하다는 것.
* *LLM 분류(llm_classify)* — 컬렉션 이름·설명을 LLM 에 주고 고르게 함. 경계 케이스용,
  문서당 LLM 1회 비용 — 맨 마지막 단계 권장. 서비스 지정 방법.
* *사용자 정의 함수(custom_function)* — Python 함수로 조직 고유 로직. 샌드박스 제약
  (import 금지 등)과 작성 계약(route(doc) 반환값).

== 조합 방식·폴백·검토 임계

다룰 내용:

* first_match(캐스케이드) vs weighted_vote(앙상블) — 선택 기준과 min_confidence/weight.
* 비용 사다리 권장 배치(규칙 → 내용 → LLM → 폴백).
* 폴백 컬렉션(미분류 Inbox) 지정 — 없으면 라우팅 실패 시 반입이 거부된다는 것.
* 검토 임계(review_below) — 저신뢰 결정을 검토 대기로 보내는 기준.

== 내용 라우팅 기준 (디스크립터)

다룰 내용:

* 컬렉션별 기준 벡터(centroid)의 개념과 계산 방법(전체/컬렉션별 재계산).
* 상태(유효/미계산/재계산 필요) 읽는 법 — 전역 임베딩 설정 변경 시 stale 처리.
* 재계산이 필요한 시점(새 문서 누적, 새 컬렉션, 임베딩 설정 변경).

== 정책 테스트

다룰 내용:

* 라우팅 테스트 탭 — 파일 업로드/경로 문자열 시뮬레이션으로 저장 없이 결과·근거(trace)
  확인.
* trace 읽는 법(라우터별 후보·점수·사유).
* 정책 저장 전후로 테스트하는 권장 절차.

== 버전 관리·롤백

다룰 내용:

* 저장 = 새 버전 생성(append-only), 버전 이력·비고 확인, 롤백 방법.
