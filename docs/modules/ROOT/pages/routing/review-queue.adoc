= 검토 대기·규칙 제안

[NOTE]
====
*구조 초안* — 목차와 각 절에 담을 내용의 방향만 잡아둔 문서입니다.
====

자동 라우팅이 *자신 없었던 결정(저신뢰·폴백)을 사람이 확인·수정* 하고, 반복되는 수정을
*규칙 제안으로 되돌려 정책을 개선* 하는 운영 루프입니다. 화면: 라우팅 > *검토 대기* 탭
(대기 건수 배지).

== 검토 대기 목록 읽는 법

다룰 내용:

* 어떤 결정이 여기 쌓이는가 — 검토 임계(review_below) 미만 또는 폴백 사용.
* 행 정보(문서·배분된 지식베이스·신뢰도·근거 배지·시각)와 문서명 클릭으로 trace
  (라우터별 평가) 펼쳐 보는 법.
* "처리된 결정 포함" 토글로 전체 이력(누가 언제 어떻게 처리했는지) 확인.

== 확인과 재배정

다룰 내용:

* *맞음 확인* — 배분이 맞았을 때(검토만 해제).
* *재배정* — 올바른 지식베이스 선택 → 문서 이동 + 새 설정으로 자동 재색인. 대상에 동일
  내용 문서가 이미 있으면 거부되는 규칙.
* 처리 권한(관리자)과 처리 기록이 남는다는 것.

== 규칙 제안 (수정 피드백)

다룰 내용:

* 동작 원리 — 같은 신호(확장자·파일명 키워드·문서 유형·소스 경로)가 같은 지식베이스로
  2회 이상 수정되면 하단에 규칙 제안이 나타남.
* 제안 카드 읽는 법(신호·값·대상·근거 건수·순도·샘플 문서).
* *정책에 반영* — 1클릭으로 정책 새 버전에 규칙 추가(언제든 롤백 가능). 반영된 제안은
  목록에서 사라지고, 이후 같은 문서는 자동으로 올바르게 배분됨.

== 운영 요령

다룰 내용:

* 검토 대기가 계속 쌓이면 — 정책 규칙 부족 신호. 규칙 제안 활용 또는 검토 임계 조정.
* 주기적 확인 권장 빈도와 배지 활용.
